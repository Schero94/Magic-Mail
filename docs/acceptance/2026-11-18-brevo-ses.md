# Acceptance: Brevo, Amazon SES, language versions, provider opens and clicks

Branch `feat/providers-brevo-ses`, stacked on `feat/provider-templates` (#20), which is stacked on `fix/provider-send-paths` (#23). The PR targets #20's branch and retargets automatically when #20 is merged.

**Status: NOT ACCEPTED.** No live run against the real Brevo and Amazon SES APIs has been recorded. `~/.config/magic-mail-live/.env` exists but has no `BREVO_*` or `SES_*` variables (checked 2026-11-18, names only). Everything else below passed. This PR must not be merged before a passing live run is recorded in [Live suite](#live-suite), like #20 and #23.

## Scope

The "later ideas" of the P1 plan (workbench `docs/plans/2026-11-16-strapi-rfc-opportunities.md`, "Not in scope"):

1. Brevo account type: send, wizard, connection check, webhooks, provider templates.
2. Amazon SES (v2, SigV4): send, wizard, connection check, SES templates, SNS event destination with signature verification.
3. Per-locale provider-template mapping (language versions).
4. Open and click counts for provider-rendered bodies from the providers' own events.
